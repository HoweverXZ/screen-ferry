# 0001. 传输层使用 TCP + TLS

- 状态：已采纳
- 日期：2026-10-31

## 背景

键鼠共享对延迟敏感，同时要传输剪贴板和文件。候选方案：

| 方案 | 优点 | 缺点 |
|---|---|---|
| TCP + TLS（Deskflow 路线） | 成熟、简单、调试工具多，按键天然可靠 | Wi-Fi 丢包时有队头阻塞；稀疏的按键丢包要等超时重传 |
| QUIC（quinn） | 多路流互不阻塞；鼠标移动可走 datagram | 用户态实现，CPU 开销更高；依赖和排查更复杂 |
| UDP + DTLS（lan-mouse 路线） | 延迟最低 | 可靠性、重传、分片都要自己做 |

## 决策

采用 TCP + rustls（TLS 1.3），每对设备建立**输入连接**和**数据连接**两条连接。

## 后果

- 大数据传输不会阻塞键鼠，这是相比 Deskflow 单连接的主要改进。
- Wi-Fi 下的短板靠应用层弥补：控制期间高频心跳（保持网卡唤醒、及时触发快速重传）、鼠标移动合并、点击携带绝对位置。
- `ferry-net` 对外只暴露"输入通道"和"数据通道"两种接口；将来如需更换为 QUIC，只改 `ferry-net`。
