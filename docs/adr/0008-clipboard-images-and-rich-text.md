# 0008 剪贴板的图片和带格式的文字

状态：已采纳

## 背景

剪贴板同步从一开始就按格式通告、按需拉取、分块传输，格式编号里也早就留了 HTML、RTF 和 PNG，
但两端只读写纯文本：截图复制过去粘不了，网页、文档里复制的内容到对方那里只剩文字。
单项大小上限固定为 32 MB，设置界面里那一项一直标着“即将支持”。

## 决定

### 格式

- 线上的格式不变：纯文本、HTML（UTF-8）、RTF、PNG。图片一律是 PNG，各平台读写系统剪贴板时自行转换。
- macOS：读写 `public.utf8-plain-text`、`public.html`、`public.rtf`、`public.png`。剪贴板里只有 TIFF 时
  （预览、Safari 复制的图片）转成 PNG；写入时只放 PNG。在访达里复制文件时剪贴板里还有一张文件图标，这时不读图片。
- Windows：文本 `CF_UNICODETEXT`，HTML `HTML Format`（带写明各段位置的文字头），RTF `Rich Text Format`，
  图片优先读 `PNG` 注册格式，没有时把 `CF_DIB` 位图转成 PNG。写入时同时放 `PNG` 和 `CF_DIB`：
  认 PNG 的程序拿到透明度，其余的拿位图（半透明的像素先叠在白底上）。剪贴板打开时只拷贝原始数据，关上之后再转换。
- 位图与 PNG 的互转、`HTML Format` 的拼装与解析是纯逻辑，放在 `ferry-core::clip_format`，在任何系统上都能测。
- 旧版对方只认纯文本，通告里不认识的格式本来就会跳过，不需要新的能力位。

### 大小与内存

- 单项上限改为设置项 `clipboard_limit_mb`（1–64，缺省 32），配置升到 `schema_version = 3`，旧文件读进来即等价。
  上限在会话中途改也立即生效，不断开连接。
- 发送方不通告超过自己上限的格式，接收方不拉取超过自己上限的格式；两种情况都记一条日志，告诉用户可以在设置里调大。
- 发送方把一种格式发完就放掉它：对方一次拉取全部格式，大图片不必一直留在内存里等下一次复制。

### 设置界面

- 状态里的剪贴板摘要新增“带格式”和图片（宽、高、预览文件）。预览文件按内容哈希存在数据目录的 `blobs/` 里，
  只保留最近一张，后台启动时清空（剪贴板历史做好之前，`blobs/` 里只有它）。
- 总览的剪贴板卡片显示图片的缩略图和尺寸；界面只按缩略图的大小解码，不把整张截图读进内存。
- 设置里的“单项大小上限”可以拖动，松手才发给后台。

## 不做

- 剪贴板历史。
- 复制的文件（访达、资源管理器里复制的文件）：用文件传输或边缘投递。
- RTFD（带图片的 RTF）、GIF 动画等其他格式。

## 后果

- 截图、网页图片、带格式的文字可以在两台电脑之间直接粘贴。
- 一次同步多传 HTML、RTF 和图片，数据量变大；图片要在发送方编码一次 PNG（Windows 位图、Mac 的 TIFF），4K 截图约需零点几秒。
