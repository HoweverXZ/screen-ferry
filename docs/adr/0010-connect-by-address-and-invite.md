# 0010 按地址连接与邀请

状态：已采纳

## 背景

被控制的一方（客户端）靠 mDNS 找到控制的一方（服务端）。可是不少网络不转发组播：公司网络、开了设备隔离的
Wi‑Fi、隔着路由器的两个网段，局域网里就“找不到其他设备”。原来只能在命令行用 `connect <地址>`，
或者在配置里写死 `server`，设置界面上没有入口；改了地址还要重启引擎。

另一个难处：被控制的那台常常没有自己的键盘鼠标（键鼠正是要从另一台借过来的），没法在它上面输入地址。

## 决定

### 被控端：按地址连接

- 设备页“在局域网里发现”旁边有“按地址连接”：填 IP、IP:端口或电脑名（不写端口用 24810）。
  只连这一次，不改 `settings.server`；连上后这次会话断线时回到这个地址重连。
- 和发现到的地址一样核对证书、按需配对；结果当场告诉对话框：连上了、地址不对、那里没有在等的 ScreenFerry、
  连不上、对面不是 ScreenFerry、版本不兼容。对话框给出该怎么办（例如允许 Windows 防火墙）。
- 单台设备的设置页上可以选“连接方式”：自动寻找，或者固定地址（就是 `settings.server`，只连这个地址，不在局域网里找）。

### 控制端：邀请一台电脑

- 客户端另外监听一个邀请端口（缺省 24811），只接受邀请连接（线协议 `channel = 5`）。
- 服务端连过去，在 `Hello.session` 里带上自己的监听端口；客户端回 `Welcome` 后关闭这条连接，
  再连到“来源 IP + 这个端口”。连上的必须是发出邀请的那台，没配对时两边照常核对配对码。
- 邀请本身不要求已经配对：它只是让客户端去连一个地址，信任仍然靠证书指纹和配对码，
  所以陌生设备发来的邀请最多让本机多连一次、弹一次配对码，用户不确认就什么也不会发生。
- 客户端正连着另一台服务端时回 `Reject(BUSY)`，不会被抢走；已经连着发邀请的这台时也回 `Welcome`，但不重连。
- 设备页的同一个位置在服务端上是“邀请一台电脑”；单台设备的设置页上有“邀请它连过来”，地址预先填好上次的。

### 记住地址

- 信任列表（`peers.toml`，升到 `schema_version = 2`）为每台设备记下最后一次连上的地址：客户端记服务端的地址和端口，
  服务端只记客户端的 IP（客户端连过来用的是临时端口，没有意义）。版本 1 的文件读进来即没有地址。
- 客户端在局域网里找不到已配对的服务端时，轮流试记下的地址，不报“正在连接”，免得界面跳来跳去。
- 服务端开始监听后，自动邀请记着地址、此刻没连上的客户端。这样两台都换过网络、组播又不通时，
  只要地址没变，服务端一开就能把对方请回来。

### 本机地址

- 设备页顶部列出本机的局域网 IPv4 地址，点一下复制，方便在另一台上照着填。
- 只列真实网卡：去掉回环、链路本地地址，以及虚拟网卡（VPN、虚拟机、容器、AirDrop 等）；`192.168` 开头的排在前面。
  地址由 `ferry-net` 列出（`if-addrs`），每次推送状态时现取。

### 本机通信

只加字段和消息，版本仍是 2：`connect_address`、`invite` 两条命令，以 `dialed` 回复结果；`local.addresses`、
`local.invite_port`、`peers[].addr`。

## 不做

- 跨网段的自动发现（单播 DNS-SD、中继、打洞）。按地址连接已经能覆盖同一个内网里组播不通的情况；
  跨公网涉及中继和穿透，是另一件事。
- IPv6 地址：列出时只给 IPv4。用户手填 IPv6 仍然可以连。
- 安装时自动添加防火墙规则。Windows 第一次运行时由系统询问，界面上在连不上时提示。
