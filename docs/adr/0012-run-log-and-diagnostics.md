# 0012 运行日志与诊断导出

状态：已采纳

## 背景

用户遇到问题时，我们需要后台的运行日志才好查原因，可原来要用户自己去缓存目录里找 `screenferry.log`。
这份日志本身也不好用：

- 时间是“启动后第几秒”，对不上“几点出的问题”；
- 往返延迟每 5 秒记一条，占了全部行数的八成，有用的内容很快被挤掉；
- 只在启动时换卷，一直运行就一直变大；
- 写着设备名、用户目录（带着用户名）和传过的文件名，直接贴到公开的问题里会泄露隐私。

## 决定

### 运行日志

- 时间改为本机时间 `2026-11-02 06:12:03.104`。时区在启动时取一次（之后进程里有了多个线程，有的系统不让再取）。
- 往返延迟改为每分钟汇总一条。
- 写满 2 MB 时改名成上一卷 `screenferry.log.1`，再开一个新的，只留这一卷。两卷的路径只有 `ferry-store` 知道。
- 设备名、文件名、路径写进日志时用 `⟦d:…⟧`、`⟦f:…⟧`、`⟦p:…⟧` 标记括起来（`ferry_types::mark`）。设置界面显示时去掉标记；
  导出时换掉标记里的内容。没带标记的正文（例如错误信息里夹着的设备名）再按已知设备的名字换一遍，以防漏网；
  “Windows”“Mac”这类通用的名字不换，它们本来也不暴露什么。以前的版本写的行没有标记，导出时不带上。
- “详细记录”：设置界面里可以临时打开 DEBUG 级别，重启后总是关着。按了哪些键、剪贴板里是什么，任何级别都不记。

### 设置界面

- “日志”页加第 6 个分段“运行日志”：
  - 上面一张卡片：导出诊断文件、复制摘要、打开日志文件夹、去 GitHub 提问题；
  - 中间是“详细记录”开关；
  - 下面是实时的运行日志：旧的在上、新的在下，可以只看警告和错误。
- 选中这个分段时每 2 秒读一次新写的内容，切走就停。

### 诊断文件

- 开头是生成时间、版本（带提交号，`xtask bundle` 打包时写进去）、系统、本机的角色和端口、显示器、权限、
  已配对的设备、主要设置和详细记录的状态，后面是两卷运行日志。存到“下载”文件夹，重名时加编号。
- “复制摘要”只带最后 200 行：GitHub 的问题描述最多 6.5 万字，整份贴不下。
- 换代号（`ferry_core::Redactor`）：本机的名字换成“本机”，其他设备依次换成“设备 A”“设备 B”，同一台设备的几个名字
  （它自己报的、本机给它起的）换成同一个代号；文件名换成“文件 1.p12”，只留扩展名；用户目录换成 `~`。
  同一个名字在整份文件里始终换成同一个代号，前后对得上。局域网地址不换，排查连接问题要用。
- 本机的日志文件保持原样，只在导出时换。
- 仓库里加 GitHub 的问题表单（`.github/ISSUE_TEMPLATE/bug_report.yml`）。“去 GitHub 提问题”用浏览器打开它，
  版本和系统经网址预先填好；诊断文件由用户自己拖进去。

### 本机通信

只加命令和字段，版本仍是 2：

- 命令：`read_run_log`、`export_diagnostics`、`copy_diagnostics`、`reveal_diagnostics`、`open_logs_folder`、`set_verbose`；
- 通知：`run_log`、`diagnostics_exported`、`diagnostics_summary`，只发给发出命令的那个界面；
- 字段：`local.system`、`local.verbose_since`。

日志文件只由后台读写，设置界面不直接碰文件。

## 不做

- 自动上传日志或崩溃报告：要服务器，也要用户事先同意，先用手动导出。
- 导出时选位置的对话框：固定存到“下载”，导出后可以在访达或资源管理器里直接显示。
- 隐去局域网地址：排查连接问题离不开它，而且只是局域网里的地址。
