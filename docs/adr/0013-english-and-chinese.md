# 0013 英文与简体中文

状态：已采纳

## 背景

所有文字原来只有简体中文：设置界面、托盘菜单、拖文件时的边缘胶囊、安装程序，后台发给界面的活动记录和提示
也是写好的中文句子。不懂中文的用户用不了，README 也只有中文。

## 决定

### 语言怎么选

- 支持英文和简体中文。系统语言是中文（`zh` 开头，简繁都算）时用中文，其他一律用英文。
- 设置里加“语言”：跟随系统（缺省）、简体中文、English。语言名用它自己的文字写，换到看不懂的语言时也认得出来。
- 选择存在配置的 `language`（`system` | `zh` | `en`），配置升到 `schema_version = 5`；旧配置没有这一项，按 `system`。
  后台和设置界面用同一个选择：界面改了，托盘菜单和边缘胶囊马上跟着换。
- 系统语言：后台用 `sys-locale` 读（`ferry-daemon` 里，经 `Host::system_language` 交给引擎）；
  设置界面用 Flutter 拿到的系统语言，系统改了语言时跟着换。两边各读各的，判断规则相同。

### 谁来说

- **设置界面**：文字放在 `app/lib/l10n/` 的 ARB 文件里（`app_zh.arb` 是源语言，`app_en.arb` 是英文），
  `flutter pub get` 生成 `AppLocalizations`。复数、哪一侧之类按 ICU 的 `plural`、`select` 写，不在代码里拼。
- **托盘菜单、边缘胶囊**：文字少，由后台按当前语言直接写（`Lang::pick(中文, 英文)`）。
- **活动记录和提示**：后台原来发写好的中文句子，界面没法换语言。现在每条另带一个 `phrase`：键加参数
  （例如 `{"key":"cursor_to_peer","args":{"name":"办公室 PC","side":"right"}}`），界面按当前语言把它说出来
  （`app/lib/state/phrases.dart`）。参数都是字符串，数字、真假也写成字符串；名字、文件名照原样带上，大小给字节数，
  界面自己换算。
  - 原来的 `text`、`detail` 保留，内容不变：界面认不出 `phrase` 的键时（后台比界面新）照原文显示，不会空白。
  - 只加字段，本机通信的版本仍是 2。
  - 后台加了新的键而界面没跟上时，界面的测试会失败：它从后台源码里找出所有的键，逐个确认认得。
- 后台遇到的问题（`state.problem`）同样带上 `port`，界面按 `kind` 说明；认不出的照 `message` 显示。

### 安装程序

- Inno Setup 自带英文（`Default.isl`）和简体中文，按 Windows 的显示语言选，不弹出选择语言的对话框；
  不是中文时用英文（排在第一个）。快捷方式的说明、安装时的状态文字放在 `[CustomMessages]` 里，两种语言各写一份。
- macOS 的 `Info.plist` 声明支持 `en` 和 `zh_CN`，缺省区域改为 `en`，系统自带的文字（例如权限对话框的按钮）
  也按这两种语言选。

### README

`README.md` 是英文，`README.zh-CN.md` 是中文，开头互相链接。两份内容保持一致，改一份时同时改另一份。

## 不做

- 翻译运行日志、诊断文件、命令行的输出：它们是给开发者排查问题用的，诊断文件还要贴进问题里，统一用中文便于对照。
- 翻译代码注释、ADR 和其他工程文档：仍然只写中文（AGENTS.md 的约定）。
- 引擎内部的错误原因（例如断开连接的原因、传输失败的原因）：它们夹在 `phrase` 的参数里照原文显示，仍是中文。
  要换成英文，得给每种错误也定义键，等用户真的遇到再做。
- 其他语言：结构已经支持，加一份 ARB、后台加一个分支即可，有人愿意维护时再加。
